# routinator-auto-test

[Routinator](https://github.com/NLnetLabs/routinator) の新しい版が出たときに、主要な機能が以前と同じように動くかを自動で確かめる、機能検証のテスト集です。
NLnet Labs の APT リポジトリから公式パッケージを Docker コンテナ (Ubuntu 22.04) に入れ、その中でテストを実行します。

## 確かめていること

スクリプトの名前は `<大分類><中分類>_<連番>_<内容>.sh` の形で、先頭の2桁が分類を表します。

| 接頭辞 | 検証内容 |
|---|---|
| `11_*` | インストール確認 (パッケージ / バージョン / 依存関係) |
| `12_*` | 設定ファイル (デフォルト値 / 配置場所 / カスタム設定) |
| `21_*` | RPKI データの取得 (rsync / RRDP / 全 RIR / タイムアウト) |
| `22_*` | データの検証 (証明書チェーン / ROA の署名 / CRL / マニフェスト / 不正なデータの拒否) |
| `31_*` | VRP の出力形式 (CSV / JSON / OpenBGPD) |
| `32_*` | VRP の内容 (プレフィックス / AS 番号) |
| `41_*` | RTR サーバの起動 (プロセスの起動 / ポートの待ち受け) |
| `42_*` | RTR プロトコルの動作 (クライアントの接続 / 差分の更新) |

## 実行方法

Docker が必要です。どちらのスクリプトも、Docker イメージのビルドから行います。

```bash
# 全件を順に実行する
./run_local_all.sh

# 1本だけ実行する
./run_in_container.sh 11_2_version_check.sh
```

RIR のリポジトリまでの往復遅延が大きい環境 (日本など) では、RRDP の取得がタイムアウトしやすいため、ローカルで実行するときはコンテナ内の TCP バッファの上限を引き上げています。
バッファの値は環境変数 `TCP_RMEM` / `TCP_WMEM` で、輻輳制御のアルゴリズムは `TCP_CC` で変えられます。`NO_SYSCTL=1` を指定すると、この調整をしません。

## GitHub Actions

| ワークフロー | 実行のきっかけ | 内容 |
|---|---|---|
| Routinator Auto-Test (Daily) | 毎日1回と手動 | APT リポジトリの最新版を確かめ、まだテストしていない版のときだけ全件を実行する。手動で実行した場合も、テスト済みの版ならスキップする |
| Routinator Self-Test (Manual) | 手動 | 版に関係なく、毎回全件を実行する |
